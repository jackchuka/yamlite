## ページ

`serve` に、かんばんボードやダッシュボードのような独自の画面を追加できます。ページは 1 つの HTML ファイルで、`window.yamlite` を通してデータを読み書きします。操作できる範囲は、`yamlite.yaml` で許可したものに限られます。

```yaml
pages:
  board:
    path: .pages/kanban.html # a dot-folder: a plain folder under the root would become a table
    title: Task board
    access: { tasks: write, people: read } # tables and views; nothing else is reachable
    sql: false # true allows SELECT over the names in access
    network: [] # origins the page may load scripts, styles, images and fonts from, and connect to
    files: { .images/: read, .uploads/: write } # files the page may read (yamlite.files.read) or also write (yamlite.files.write); a folder ends in /
    ai: true # lets the page call the host's AI model; { maxOutputTokens: 2048 } raises the default 1024 (at most 8192)
```

最初は [`examples/pages/kanban.html`](../../examples/pages/kanban.html) から始めるのがおすすめです。これを `.pages/` にコピーし、先頭の `TABLE`、`KEY`、`GROUP`、`TITLE` を設定して、上のように宣言します。[`examples/pages/summary.html`](../../examples/pages/summary.html) は、AI にレコードを要約させるページの例です。[`examples/pages/gallery.html`](../../examples/pages/gallery.html) は、テーブルの `image` カラムを一覧表示し、各ファイルを `yamlite.files.read` で表示します。

そのページだけを見せたい相手に共有するには、ページを開いて **アプリのリンクをコピー** をクリックします。リンクは `/-/apps/<name>/` で終わり、ページ自身のタイトルと見た目で、そのページだけが表示されます。サイドバー、テーブル、SQL コンソール、コマンドメニュー、ほかのレコードへのリンクはありません。編集があると、下部のバーに編集の件数と **レビューに出す** が表示されます。埋め込み先のホストは、`appFooter` マウントオプションで、このバーの左側に独自のコントロールを追加できます。アプリのリンクが表示中とは別のブランチを開くホストは、`branchAppLink` マウントオプションで、その隣に **ブランチのリンクをコピー** を追加できます。レビュー中の編集を、反映前に見せるためのものです。`#` 以降は、ページが自分の中でどこにいるかを表し、ページが `yamlite.history` で設定します。そのため、再読み込み、戻るボタン、コピーしたアドレスで同じ位置に戻れます。これを変更しても、アプリからは出ません。このリンクは、エディターを見えなくするだけで、使えなくするものではありません。アドレスから `-/apps/<name>/` を取り除けば、UI のほかの部分にも到達できます。`serve` でコピーしたリンクにはトークンが含まれず、メールやチャットなど別のサイトからリンクを開くと、ログインの Cookie が送られません。代わりに、`serve` が表示した URL のオリジンで、そのトークンを付けた `/-/apps/<name>/?token=…` を共有してください。`serve` はアプリを試すためのものです。チームで共有するには、閲覧者ごとに専用のブランチを用意するホストを使ってください。`export` でも、含めたページごとに、`-/apps/<name>/` に同じ入口ができます。末尾のスラッシュを付けて開いてください(静的ホストは自動で付けます)。付けないと、ページの相対パスが 1 階層上に解決されてしまいます。

| 呼び出し                                                                                                       | 動作                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| -------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `await yamlite.ready`                                                                                          | `{ page, title, access, sql, network, files, readOnly, ai }`。`ai` は、ページに `ai` があり、ホストがキーを持っているときは `{ provider, models }`、それ以外は `null`                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `yamlite.rows(table, { filter, sort, search, limit, offset })`                                                 | `{ rows, total }`。テーブルとビューを読み取り、テーブル画面と同じフィルターと検索を使う。`limit` は 500 まで                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `yamlite.get(table, key)`                                                                                      | `{ row, file }`。テーブルのみで、ビューを指定すると 400                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `yamlite.create(table, key, values)` / `update(table, key, values, { base })` / `remove(table, key, { base })` | `write` が必要。`base` は、ページが最後に読み取ったレコード、またはそのうちページが依存しているフィールド。`update` は、保存するフィールドが `base` の後に変更されていると、ステータス 409、`extra.stale`(該当フィールド)、`extra.current`(現在のレコード)で失敗する。`remove` は、`base` のどのフィールドかが変更されていると失敗する。`base` を省略すると、この確認は行われない                                                                                                                                                                                                                                                       |
| `yamlite.sql(select)`                                                                                          | `sql: true` が必要。`access` にある名前に対する SELECT を 1 つ実行する                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `await yamlite.files.read(path)`                                                                               | `path` が、そのページの `files` のいずれかの項目(`read` または `write`)に一致し、拒否されたパスでないことが必要。拡張子に応じた型(`image/png`、`image/jpeg`、`image/webp`、`image/gif`、`image/svg+xml`、`application/pdf`、`text/plain`、それ以外は `application/octet-stream`)の `Blob` で解決され、`URL.createObjectURL` に渡せる。対象は、閲覧者が開いているブランチまたはコミットのファイルで、10 MB まで。`path` がどの項目にも一致しないときは 403、ファイルがないときは 404、上限を超えるときは 413                                                                                                                             |
| `await yamlite.files.write(path, blob, { base })` / `files.delete(path, { base })`                             | `path` が `write` の項目の配下にあることが必要。`write` は PNG、JPEG、GIF、WebP、PDF のファイル(バイト列が拡張子と一致していること。10 MB まで)を保存し、必要なフォルダーも作成して、`{ sha256 }` で解決される。`delete` はファイルを削除する。`base` は、ページが `files.read` で最後に受け取った `Blob`、最後の `files.write` が返した `sha256`、またはそこにファイルがないと想定しているときの `null`。その後にファイルが変更されていると、ステータス 409 と `extra.current`(現在の内容の SHA-256。ファイルが 10 MB を超えるときはなし)で失敗する。`base` を省略すると、この確認は行われない                                         |
| `yamlite.on("change", ({ tables, files }) => …)`                                                               | 同期によって、ページが読み取れるテーブルやビューが変わったとき(`tables`)と、ページの `files` 配下のファイルがディスク上で変わったとき(`files`。ルートからの相対パス)に、誰が変更したかにかかわらず呼ばれる                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `yamlite.theme` / `yamlite.on("theme", ({ theme }) => …)`                                                      | 現在のテーマ(`light` または `dark`)と、変わったときの呼び出し                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `yamlite.ai.generate({ system, prompt, schema, model, maxOutputTokens })`                                      | `ai` が必要(`ai` のないページは 403)。`{ text }`、または `schema`(JSON Schema)に一致する `{ object }` を返す。`prompt` は文字列、または `{ role: "user" \| "assistant", content }` のリスト。`model` は `ready` の `ai.models` のいずれかで、デフォルトは先頭のもの。`maxOutputTokens` でページの上限を下げられる。常にホストのキーで実行され、ページが渡したキーは使われない。ホストにキーがないときは 503 と `extra.code: "no_key"`、混み合っているときは 429 と `extra.retryAfter`(秒)、プロバイダーが失敗したときは 502 で失敗する。502 では `extra.provider` がプロバイダーの ID で、プロバイダー自身のテキストが `message` に入る |
| `yamlite.ai.stream({ system, prompt, model })`                                                                 | `schema` がない点を除いて同じ。テキストの差分を返す非同期イテラブルで、`for await (const text of yamlite.ai.stream(…))` のように使う。ループを途中で抜けると、呼び出しがキャンセルされる                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `yamlite.open(table, key)`                                                                                     | YAMLite 自身のフォームでレコードを開く。テーブルのみで、ビューを指定すると 400                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `yamlite.history`                                                                                              | ページが自分の中でどこにいるかを表す。ルーターが受け取る `history` パッケージの形(`location`、`push`、`replace`、`go`、`back`、`forward`、`listen`、`createHref`)をしている。アプリ内ではアドレスの `#` 以降に保持され、`back` と `go` はアプリの中にとどまる。`push(to, state)` と `replace(to, state)` は、ページの外のパスや 2048 文字を超えるパスを渡すと例外を投げる。`state` は structured clone できる値でなければならず、戻る・進む操作では `location.state` として、再読み込み後は JSON として返ってくる                                                                                                                       |

エラーは `yamlite.YamliteError`(`status`、`message`、`extra`)で reject されます。

### 見た目

すべてのページに、UI の色とフォントが CSS 変数として渡されます。テーマを切り替えても、再読み込みなしで追従します。

| 変数                                                                | 用途                                                                       |
| ------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| `--y-bg`, `--y-panel`, `--y-panel-2`, `--y-line`                    | 面と罫線                                                                   |
| `--y-text`, `--y-muted`                                             | テキスト                                                                   |
| `--y-accent`, `--y-accent-fill`, `--y-accent-soft`, `--y-on-accent` | 強調                                                                       |
| `--y-ok`, `--y-warn`, `--y-warn-soft`, `--y-err`, `--y-err-soft`    | 状態                                                                       |
| `--y-chip`, `--y-chip-text`                                         | チップ                                                                     |
| `--y-font`, `--y-mono`                                              | Outfit と JetBrains Mono(ラテン文字)。ほかの文字にはシステムフォントを使う |

ネイティブのフォームコントロールとスクロールバーが、テーマ(`color-scheme`)に従うのは、`data-yamlite-ui` を付けたページだけです。

`<html>` には `data-theme="light"` または `"dark"` が付きます。`yamlite.theme` はこれを読み、`yamlite.on("theme", ({ theme }) => …)` は変わったときに呼ばれます。

`<html>` に `data-yamlite-ui` を付けると、標準の要素にも UI の見た目が適用されます。対象は、`body`、見出し、リンク、`button`(塗りつぶしにするには `.y-primary`)、`input`、`select`、`textarea`、`table`(固定ヘッダー、セルの折り返し)、`pre`/`code`、`details`/`summary` です。次のクラスも使えます。`.y-chip`(`.y-ok`、`.y-warn`、`.y-err` を併用可)、`.y-card`、`.y-toolbar`、`.y-muted`、`.y-link`。これらはすべて `:where()` の中にあるので、自分で書いたルールが常に優先されます。

変数名とクラス名はページ API の一部です。名前を変更すると、互換性のない変更になります。

- ページは、YAMLite のセッションにアクセスできないサンドボックス化されたフレームで動きます。すべての呼び出しは YAMLite を経由し、`access` に照らして検証されます。SQL は読み取り専用の接続で実行され、`access` にないテーブルは SQLite 自身が拒否します。
- `network` は Content Security Policy で強制されます。ページが読み込むものと、接続できる先を制限します。オリジンを宣言すると、ページは、`access` を通じて読み取れるものを含むデータを、そのオリジンへ、お使いのマシンの外に送信できるようになります。
- `ai` を指定すると、ページは `access` を通じて読み取れるものをすべて、ホストの AI プロバイダーに送信できます。料金はホストのキーに課金されます。
- どのページも、`network: []` であっても、自分のフレームを、データを URL に含めた別のサイトへ移動させることで、データを漏らせます。その場合、YAMLite はページを切断しますが、データはすでに外に出ています。実行するスクリプトと同じように、信頼できるページだけを宣言してください。
- `files` は `access` と同様の許可です。各項目は `read` か `write` で、ページは、宣言したフォルダーの配下にあるすべてのファイルを読めます。ページが読めるものは、レコードと同じく、ページの移動によって外に出る可能性があります。`/` で終わる項目はフォルダー、それ以外の項目は特定の 1 ファイルです。`..`、絶対パス、`.yamlite/` 内の項目、`yamlite.yaml` を指す項目は設定エラーです。`read` と `write` 以外のレベルも同様です。`files` の指定にかかわらず、ページは、YAMLite の状態フォルダー、データベース(と、その `-wal`、`-shm`、`-journal` ファイル)、設定ファイルを読めません。広いフォルダーを指定しても、それらは 403 になります。シンボリックリンクはたどられ、許可されたパスの内側にとどまる必要があります。
- `write` の項目は、その配下でページがファイルを追加、置換、削除することを許可します。ただし、対象は、バイト列が拡張子と一致する画像と PDF だけです。HTML、SVG、その他、ファイルが後で配信される場所でスクリプトとして実行されかねないものは書き込めません。ページは、YAMLite 自身のファイルに書き込めず、シンボリックリンクされたファイルを通じても書き込めません。シンボリックリンクされたフォルダーは、ページが書き込みを許可されたパスにつながっている必要があります。書き込まれたファイルは、ほかの編集と同じく作業ツリーに反映されるので、**レビューに出す** に一覧表示されます。`write` は、ページが管理するものだけを入れたフォルダーに限って許可してください。
- `serve` は作業ツリーを読むので、`files` の項目は、ローカルの `.env` やビルド出力のように、git が追跡していないファイルも対象にします。ページに見せたいものだけを入れたフォルダーを宣言してください。
- [エクスポート](check-query-export.md#エクスポート)では、ページは読み取り専用で、`access` ではデータを隠せません。書き出した `db.sqlite` はダウンロードでき、`sql: true` なら書き出したすべてのテーブルを読めます。`access` にエクスポートから除外したテーブルを含むページは、警告を出してスキップされます。エクスポートは、ページが宣言したファイルも `data/files/` にコピーします。各ファイルには `.bin` の接尾辞が付くので、ホストはページとしてではなく、ダウンロードとして配信します。エクスポートをデプロイすると、それらのファイルは公開されます。10 MB を超えるファイルは、警告を出してスキップされます。
