## データの扱い

### テーブル

| ルート直下の項目        | テーブル | レコード                                                                                                                                                            | キー                                                     |
| ----------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| `tasks/`(ディレクトリ)  | `tasks`  | フォルダーとそのサブフォルダー内の `*.yaml` / `*.yml` ファイル 1 つにつき 1 件。`files: "tasks/**/*.{yaml,yml}"` と同じ意味で、この指定が必要なのは変更するときだけ | 拡張子を除いたパス(`id`)。`buy-milk`、`archive/buy-milk` |
| `people.yaml`(ファイル) | `people` | トップレベルのリストの各項目                                                                                                                                        | `id` フィールド                                          |

ドットで始まるファイルとフォルダー、`node_modules` は、どの階層でも無視します。ルートの `yamlite.yaml` も対象外です。ほかに外したいものは [`ignore:`](configuration.md#ファイルを無視する) に書きます。ルートにある YAML ファイルのうち、リストではなくマップやスカラー値を持つもの(`pnpm-lock.yaml` など)は、`yamlite.yaml` で宣言しない限りテーブルになりません。シンボリックリンクのファイルとディレクトリは、リンク先をたどります。

ディレクトリのテーブルでは、ファイル自身の `id` フィールドに、完全なキー(`archive/buy-milk`)とファイル名だけ(`buy-milk`)のどちらを書いてもかまいません。それ以外の値は警告になり、パスが優先されます。ネストしたキーで行を挿入するとフォルダーが作られ、フォルダー内の最後のレコードを削除すると、空になったフォルダーも削除されます。ほかのテーブルのフォルダー内で宣言したテーブルは、その glob に一致するファイルを受け持ち、外側のテーブルはそのファイルを扱いません(`archive: { files: "tasks/archive/*.yaml" }`)。フォルダー名を変更すると、レコードの削除と再追加になります。大きなフォルダーの名前を変えると、大量削除のガードに引っかかって `--force` が必要になることがあります([安全性](how-it-works.md#安全性)を参照)。

### 型

| YAML の値               | カラムの型 | 保存形式                            |
| ----------------------- | ---------- | ----------------------------------- |
| `true` / `false`        | `BOOLEAN`  | `1` / `0`                           |
| `42`                    | `INTEGER`  | 整数(大きな値も正確に保持)          |
| `1.5`、または整数と小数 | `REAL`     | 実数                                |
| `hello`, `2026-10-01`   | `TEXT`     | テキスト(YAML 1.2 では日付は文字列) |
| マップとリスト          | `JSON`     | JSON テキスト                       |

YAML に新しいキーが現れると、新しいカラムが自動的に作られます。推論で既存のカラムの型が変わることはありません(型に合わないスカラー値は、警告を出したうえでそのまま保存します)。型を変えるには、`yamlite.yaml` で型を宣言してください。詳しくは[カラムの型](configuration.md#カラムの型)を参照してください。

### 入れ子の値

入れ子のデータは、トップレベルのキーごとに 1 つの `JSON` カラムに保存されます。SQLite の JSON 関数で扱えます。

```yaml
# tasks/release.yaml
title:
  en: Write release notes
  ja: リリースノートを書く
```

```sql
select json_extract(title, '$.ja') from tasks;                    -- read a nested value
update tasks set title = json_set(title, '$.ja', '書き直す');      -- written back as a map
select * from tasks, json_each(tags) where json_each.value = 'a'; -- filter on list items
```

フィールドは、レコード全体を通して、**常にスカラー値であるか、常にマップかリストである**必要があります。新しいフィールドで両方が混在すると、どのレコードがどちらかを列挙したエラーを出して、そのテーブルの同期を止めます。既存のカラムに合わないレコードは、警告を出してスキップします。データベースの JSON カラムに、マップでもリストでもない値が入っているとき(たとえば手作業の `UPDATE` のあと)は、SQL で直すかファイルを編集するまで、その行は YAML に書き戻されません。フィールドを移行する場合(たとえば `title` → `{en, ja}`)は、`yamlite.yaml` で宣言(`columns: { title: JSON }`)してから同期してください。カラムが変換され、まだ変換されていないレコードは、ファイルを変更するまで警告として表示されます。

### 展開ビュー

レコード内のリスト(プロジェクトのマイルストーン、マイルストーンのタスクなど)は、行として検索できます。`expand` で宣言すると、同期のたびに、リストごとに読み取り専用の SQLite ビューが更新されます。

```yaml
tables:
  projects:
    expand:
      milestones: # the JSON column → view projects__milestones
        columns: { points: INTEGER } # optional: pin a type
        expand:
          tasks: # a field of each milestone → view projects__milestones__tasks
            references: { owner: people }
```

```sql
select p.title, m.title, t.owner
from projects p
join projects__milestones m on m.projects_id = p.id
join projects__milestones__tasks t on t.projects_id = m.projects_id and t.milestones_idx = m.idx;
```

- ビューの先頭のカラムは、その行の位置を表します。テーブルのキー(`projects_id`)、上位のリストでの位置(`milestones_idx`。名前が重複すると `children_idx_2` のように `_2`、`_3`、… が付きます)、そして自分自身の位置です。リストなら `idx`、マップなら `key` になります。その後ろに、項目のフィールドごとに 1 カラムが並びます。マップでない項目(`tags: [a, b]`)は、`value` カラムに入ります。
- カラムと型は、同期のたびにデータから推論します。型を固定するには `columns` を使います。`yamlite.yaml` には何も書き戻しません。
- ビューは読み取り専用です。編集するときは、YAML を編集するか、テーブルの JSON カラムを更新してください。`serve` は、ビューをテーブルの下に一覧表示し、行の元になったレコードを開きます。
- ビューの `references` はテーブルと同じように検証され、`status` は予定されている `+ view` / `− view` の変更を表示します。ビューにできないリスト(フィールドが JSON カラムでない場合や、同名のビューが手作業で作られている場合)は、警告になります。
- Web UI では、テーブルのスキーマ(**ルールを編集**)から展開ビューを追加・削除できます。削除すると、そのビューのルールも一緒に削除されます。
